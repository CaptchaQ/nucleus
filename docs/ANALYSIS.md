# Анализ подходов к демаршу ИИ-проектов

Перед проектированием `nucleus` мы изучили 7 открытых экосистем и выделили,
что каждая решает для агентной разработки лучше всего. Ниже — выводы, которые
легли в архитектуру.

## Хронология ключевых провалов агентной разработки

```
заказчик ("я хочу приложение")  ──gap──►  агент ("вот сайт")
        ▲                                    │
        └──────── misalignment ◄───────────  нет общего языка
```

Этот разрыв — центральная проблема, которую addrерсит слой grill-механизмов.

## Что взять из каждой системы

| Система | Проблема, которую решает | Что взял nucleus |
|---------|--------------------------|------------------|
| mattpocock/skills | коммуникационный разрыв заказчик↔агент | фаза **допроса** (grilling), ADR + глоссарий, карта decision tickets (wayfinder) |
| affaan-m/ECC | разрозненные навыки не оркестрируются | полный харнес **plan→test→implement→review→verify→remember→improve**, memory store, оркестр субагентов |
| prompts.chat | нет общего каталога промптов-ролей | **MCP-сервер** ролей/промптов для субагентов оркестра |
| google-labs-code/stitch-skills | дизайн-видение не становится кодом | скилы дизайн-генерации: generate-design → react-components → shadcn-ui |
| emilkowalski/skills | у агентов нет вкуса | скилы полировки UI, анимаций, выбора библиотек |
| keepsimple.io/uxcore | продукты не учитывают восприятие | библиотека когнитивных искажений + nudge → **рубрики UX** |
| crimeacs/auto-improve | "улучшение" = переписывание вслепую | **GAN-цикл**: mutate → score (отдельной моделью) → pairwise-judge → commit |

## Решения, принятые по результатам анализа

1. **Фазы как конвейер.** Каждая фаза (init → wayfind → load → orchestrate →
   improve) — отдельный CLI-командой и отдельным модулем с общими типами из
   `src/types.ts`. Проверяемо независимо.
2. **Гибридный лоадер.** Не выбираем один способ доставки скилов — используем
   три одновременно: внешние через `npx skills add <repo>`, кастомные в
   `.agent-forge/skills/`, встроенные в `skills/`. Каталог объединяет всё.
3. **Decision tickets, а не спринты.** Над образом светлого будущего строим
   карту решений (research/prototype/grilling/task), решаем их по одному,
   вычёркивая туман к цели. Work за границей цели классифицируется **вне
   рамок**, а не решается в пути.
4. **Оркестр субагентов.** Роли (planner/researcher/implementer/reviewer/
   tester/designer/security/docs/improver) берут скилы из каталога через
   таблицу `ROLE_BY_SKILL`; общая память — файловый store.
5. **Улучшение через критерий, а не вкус.** Артефакты улучшает отдельная
   модель против рубрики, сравниваемая парнями в двух порядках, с коммитом в
   git — история улучшений воспроизводима.
6. **Расширяемость как первоклассный скил.** `nucleus skill add` изучает
   источник, создаёт пространство `.agent-forge/skills/<name>/`, реиндексирует
   каталог и обновляет README — «изучи и добавь скилл» встроено в продукт.
