# improve — GAN-цикл авто-улучшения

Когда человек говорит «сделай лучше» — не переписывай вслепую и не «улучшай
наугад». Работай циклом: **мутатор → судья → парный гейт → чекпойнт**.
Мутатор и судья — разные модели/контексты (анти-slop). Победитель
зафиксирован, проигравший отброшен. Цикл не зацикливается — три стопора.

## Когда применять

- Доработка существующего кода/README/промптов/копи.
- Обратная связь: «не нравится», «медленно», «баг», «полировка».
- Повторяющийся Block-паттерн из `review` (мета-лупа: запах → improve цикл).

## Правила (анти-slop ядро)

1. **Судья ≠ мутатор.** Оценивающая и мутирующая модели — разные. Оценка
   каждой кандидатуры — свежий вызов, не тот же контекст, что у мутатора.
   Никогда не суди своё же в том же окне.
2. **Парный гейт keep/discard.** Кандидат и чемпион судятся head-to-head в
   **обоих порядках** (`[Cand, Champ]` и `[Champ, Cand]`) — отменить
   позиционное смещение. **Keep только если кандидат голосов больше, чем
   чемпион; ничья = discard.** Никакого «score выше → бери».
3. **Best-of-N.** N хирургических диффов одним промптом мутатора, затем
   парный гейт. Один неудачный draw не стопорит цикл.
4. **Информированный мутатор (фидбек-лупа).** Промпт мутатора получает:
   (а) разбор судьи по наимизшим измерениям рубрики, (б) **PREVIOUS ATTEMPTS**
   history — «не повторяй уже проваленные идеи», (в) саму рубрику. Это
   заставляет цикл двигаться к слабым местам, а не кружиться.
5. **Никаких фейковых метрик.** Не показывай монотонный «лесеночный score» —
   показывай настоящий парный итог (`keep/discard`, margin). Зрительное
   «monotonically rising» — враньё, которое плодит доверие к шуму.
6. **Честный checkpoints.** Человек в цикле: после N итераций —
   checkpoint-гейт (человек спот-чек current champion), не накапливай
   непроверенные поколения.

## Анти-зацикливание — три стопора

1. **Жёсткий `--max-iterations`** (по умолчанию 6 для кода, 4 для текста).
2. **`--threshold`** → `[CONVERGED]` break, когда каждая dim рубрики близка
   к целевому диапазону.
3. **Детектор плато:** `consecutive_discards >= 3` → не «жми сильнее», а
   **перечитай рубрику** свежим углом (re-run evaluate single-shot) и обнули
   счётчик. Если плато повторяется — стоп, человек разбирается.

## Рубрика = spec

- Рубрика — md-файл со взвешенными измерениями, сумма = 100.
- Заякорь шкалу: «50 avg / 70 good / 90+ exceptional».
- Формулировки **поощрением** («award N when X»), не штрафом.
- 5–7 независимых dim, специфичных под артефакт.
- Если рубрики нет — выведи её из артефакта + цели (`--goal`) на старте;
  согласуй с человеком.
- **Мета-лупа:** когда плато — прокачай саму рубрику (сузь dim, поправь
  веса), потом снова против неё. Импрувер и spec поднимаются по очереди.

## Хирургические диффы и краш-безопасность

- Мутатор выдаёт **surgical diff** (точечные правки), не «перепиши файл».
- Применение — лестница: exact → unicode-canon → fuzzy match, с guard от
  делимитеров. Некорректный патч **пропускается**, не портит файл.
- Никогда не применяй непроверенный diff автоматически.

## Git как чекпойнт

- Каждый KEEP — commit на ветке `improve/<tag>` (или запись в
  `.agent-forge/improvements.md` если git неприменим).
- `git diff <base> improve/<tag>` = журнал улучшений, diffable прирост.
- Откатить цикл = checkout base. Нет потери.

## Цикл

1. **Зафиксируй критерий** → рубрику (выведи из артефакта + цели, согласуй
   с человеком, если её нет). Плохой критерий — останови и спроси.
2. **Заякорь чемпион:** текущий артефакт. Базлайн — оценка судьёй.
3. **Раунд:** мутатор генерит N surgical diffs (с фидбеком судьи + history
   проваленных идей + рубрикой) → парный гейт keep/discard по каждому
   (judge head-to-head обоих порядков).
4. **Best-of-N:** если хоть один keep с положительным margin → чемпион
   обновлён, commit на `improve/<tag>`. Иначе → discard, счётчик плато +1.
5. **Стопор:** max-iterations / converged / плато(3) → выход.
6. **Checkpoint-гейт** (каждые N итераций): человек спот-чек чемпион,
   решение: продолжить / остановиться / перечитать рубрику.

## Результат / критерий готовности

- Чемпион применён к артефакту (commit-ы на `improve/<tag>` или записи в
  `.agent-forge/improvements.md`): `файл | критерий | итерация | результат
  (keep/discard, margin)`).
- Рубрика зафиксирована (отдельный md, weight sum=100) — её можно улучшать.
- Достигнут один из стопоров (не «дороделано»).
- Человек видел checkpoint и подтвердил продолжение/стоп.
- Откат возможен одной командой (checkout base).

## Чего избегать

- Не «улучшай» без критерия — «красивее» не критерий.
- Не меняй несколько осей за раунд — результат непроверяем.
- Не показывай фейковый растущий score — только настоящий парный итог.
- Не накапливай поколения без checkpoint-гейта.
- Не оптимизируй буквально слова рубрики (узкая рубрика → зацикливается),
   сначала прокачай рубрику.
