# skill-add — добавление нового скила

Набор скилов живёт в `skills/<имя>/SKILL.md`. Когда в работе возникает
повторяемая процедура, которой нет в наборе — добавь её как скил.

## Когда применять

- Одна и та же последовательность действий встречается второй раз.
- Человек просит: «запомни, как мы это делаем», «сделай скил».
- Известная методика (TDD, code review, деплой, …) должна стать
  обязательной частью работы.

## Не применять

- Единичная задача — это не скил, просто выполни её.
- Если процедура уже описана в другом скиле — дополни тот, не плоди.

## Шаблон скила

```markdown
---
name: <kebab-case-имя>
description: <одно предложение: когда применять и что даёт. Без слова "skill">
user-invocable: false
---

# <имя> — <короткое название>

<1–2 абзаца: что это и в какой фазе проекта применяется>

## Когда применять

- <условие 1>
- <условие 2>

## Правила

1. <правило — обязательное, иначе скил бесполезен>
2. <правило>

## Шаги

1. <шаг с ожидаемым результатом>
2. <шаг>

## Результат / критерий готовности

<что должно существовать после применения скила>
```

## Правила добавления

1. **Имя** — kebab-case, короткое, без «skill-» префикса и без названия
   проекта. `code-review`, `tdd`, `deploy` — ок; `my-super-skill` — нет.
2. **Description** — начинается с глагола («Провести…», «Разбить…») и
   говорит *когда применять*, а не что скил делает в теории.
3. **Каждый скил — самодостаточен.** Агент должен суметь выполнить его,
   прочитав только SKILL.md (плюс profile.json/plan.md проекта).
4. **Правила — обязательные требования**, а не пожелания. Если правило
   можно нарушить без последствий — оно не правило, убери.
5. Новый скил автоматически попадает в таблицу в AGENTS.md — обнови её
   (строка «| `skills/<имя>/SKILL.md` | … |»).

## Результат

`skills/<имя>/SKILL.md` + строка в таблице скилов AGENTS.md.
