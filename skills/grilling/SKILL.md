# grilling — интервью до идеального старта

Прежде чем писать код, заточи идею. Цель — **дойти до общего понимания** с
человеком: что именно строим, какие решения приняты, что за пределами. Без
этого агент строит не то, что нужно.

## Когда применять

- Человек говорит «хочу сделать X» / «создай проект» и в папке нет
  `.agent-forge/profile.json` (или профиль устарел — см. ниже).
- Человек называет крупное изменение, выходящее за рамки профиля.
- НЕ применяй, если человек явно сказал «не спрашивай, делай» или это правка
  по уже зафиксированному профилю мелкого масштаба.

## Механика — дизайн-дерево с фронтиром

Интервью — это **дерево решений**. Каждое решение ветвится в решения, которые
от него зависят. Не задавай вопросы «по списку сверху вниз» — работай
**раундами**, двигая **фронтир**.

**Фронтир** — множество решений, чьи предпосылки *уже* выяснены: вопросы,
которые можно задать *сейчас*, не угадывая ответы, которые ещё не прозвучали.

Раунд:
1. Вычисли фронтир (все решения, чьи предпосылки закрыты).
2. Задай **весь фронтир за один раунд**: номеруешь каждый вопрос и даёшь
   **рекомендованный ответ** (не оставляй пустоту — recommendations вместо
   тишины ускоряют и обнажают твои предположения).
3. Жди ответов человека, прежде чем переходить к следующему раунду.

Каждый раунд перестраивает дерево: решённые вопросы двигают фронтир вперёд и
разблокируют зависимые. Пересчитывай фронтир и задавай следующий раунд.
Вопрос, чей ответ зависит от ещё открытого в этом раунде решения, принадлежит
*более позднему* раунду — не этому.

### Формат вопроса

```
❓ **Q1** — <тема вопроса>: <body, возможен multi-choice>

➡️ <твой рекомендованный ответ с кратким «почему»>
```

## Правила

1. **Факты — твоя работа, решения — человека.** Если фронтир-вопрос требует
   факта из окружения (файлы, инструменты, версии, API), найди его сам —
   отправь субагента на разведку, не спрашивай человека о том, что можно
   посмотреть. Не блокируйся на этом: разведка — открытая предпосылка, вопросы
   ниже по дереву ждут субагента, остальной фронтир спрашивай сейчас.
2. **Решения — человека, без подмены.** Не отвечай за него. Дай рекомендацию
   и жди. Человек говорит «да/нет/другой вариант» — решение его, не твоё.
3. **Не ограничивай число вопросов.** Сессия закончена, когда фронтир пуст:
   все ветки дерева пройдены, ничего не предполагается молча. Маленький
   проект — 1–2 раунда; большой — map через `wayfinder` после.
4. **Один вопрос — одна идея.** Не слепи compound-вопросы. Лучше два
   нумерованных, чем один двусмысленный.
5. **Записывай в профиль по мере кристаллизации.** Не вручную. Где решение
   материализовалось — туда и пишу: `profile.json` (destination/domain/stack/
   outOfScope), `CONTEXT.md` для терминов (см. `domain`), ADR для
   труднообратимых решений (см. `domain`). Не батчируй — лови в момент.
6. **Ничего не предполагай молча.** Дойдя до фронтир-противоречия (твой
   ответ против сказанного человеком), остановись и уточни.

## Что собрать в профиль

К концу интервью в `.agent-forge/profile.json` должно быть:
- **name** — короткое имя проекта (slug).
- **destination** — 1–2 строки: что значит «дойти до конца». Финальный артефакт.
- **domain** — fullstack / backend / frontend / cli / mobile / data / ...
- **stack** — языки, фреймворки, харнесс (opencode/claude-code/codex/omp),
  issue-tracker (github/linear/local-markdown).
- **qualityGuardrails** — что для проекта «готово»: types, tests, linter,
  smoke, e2e — обязательные.
- **outOfScope** — что *сознательно* за пределами (мобильное приложение,
  офлайн, мультипоток…). В план и код не попадает никогда.
- **glossary** — ubiquitous language: термины проекта (живёт в `CONTEXT.md`,
  здесь — ссылка; см. скил `domain`).
- **openRisks** — что ещё содержит туман (туман ≠ out-of-scope; напротив, в
  области пути но ещё не резкие) → кандидаты на `wayfinder`.

## Результат / критерий готовности

- `.agent-forge/profile.json` существует и заполнен.
- `CONTEXT.md` создан при появлении первого термина (`domain`-скил).
- Фронтир пуст: человек подтвердил общее понимание.
- Ты показал человеку **одним экраном** итог: destination, domain, stack,
  outOfScope, glossary-указатель, openRisks.
- **Не действуй, пока человек не подтвердит** общее понимание.

## Что дальше

- Маленький проект (меньше сессии) → `spec` → `implement`-цикл.
- Слишком туманно / больше сессии → `wayfinder` (карта тикетов).
- Подгрузка проектных скилов под стек → `stitch`.
