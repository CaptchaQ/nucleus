# plan — декомпозиция проекта

После того как профиль зафиксирован (`.agent-forge/profile.json`), разбей
проект на **этапы** и **задачи** до того, как писать код.

## Когда применять

- Сразу после `interview` (профиль готов).
- Когда проект усложнился и старый план не покрывает новую реальность.

## Правила

1. **Этапы идут от destination.** Destination из профиля — конечная цель.
   Каждый этап приближает к ней и **проверяем** (у этапа есть явный
   результат: «работает X», «страница рендерится», «API отвечает»).
2. **Не более 3–5 этапов.** Больше — значит план не готов, объединяй.
3. **Каждая задача — действие одного агента за одну сессию.** Если задача
   больше — разбей.
4. **Стек — из профиля.** Не предлагай в плане технологии, которых нет в
   `profile.json` (languages / frameworks). Нужно что-то новое — сначала
   уточни у человека, потом правь профиль.
5. **Вне скоупа — не включай.** То, что в `outOfScope`, в план не попадает
   никогда, даже «на потом».
6. Опирайся на `glossary` из профиля — используй термины человека.

## Формат — .agent-forge/plan.md

```markdown
# План: <имя проекта>

Destination: <из профиля>

## Этап 1: <название> — <проверяемый результат>

- [ ] Задача 1.1 — <действие, ожидаемый результат>
- [ ] Задача 1.2 — <действие, ожидаемый результат>

## Этап 2: <название> — <проверяемый результат>

- [ ] Задача 2.1 — ...
```

## Порядок работы

1. Прочитай `.agent-forge/profile.json`.
2. Составь черновик этапов. Покажи человеку одной строкой:
   «План: Этап 1 — …, Этап 2 — …, Этап 3 — …». Спроси: «ок?»
3. После подтверждения запиши полный план в `.agent-forge/plan.md`.
4. Начни Этап 1. Если задача большая (нужно несколько ролей сразу) —
   передай управление скилу `orchestrate`.

## Когда план считается готовым

- Каждый этап имеет проверяемый результат.
- Каждая задача выполнима за одну агентскую сессию.
- Человек подтвердил план.
