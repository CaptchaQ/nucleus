# orchestrate — оркестрация по ролям

Когда задача из плана слишком велика для одного агента в одной сессии —
разбей её на **роли** с чёткими границами. Каждая роль — это отдельный
проход, отдельная ответственность.

## Когда применять

- Задача покрывает несколько слоёв сразу (фронт + бэк + тесты + доки).
- Один проход «написать всё сразу» даст необозримый дифф.
- План говорит, что этап требует нескольких видов работы.

## Роли

| Роль | Владеет | Не делает |
|------|---------|-----------|
| **planner** | декомпозицией, порядком работ, критериями готовности | не пишет код |
| **researcher** | поиском фактов: API-поверхности, доки, версии, best practices | не проектирует |
| **implementer** | написанием кода под контракт (из плана и профиля) | не меняет контракт |
| **reviewer** | свежим взглядом: баги, пропущенные требования, качество | не пишет код за implementer |
| **tester** | проверкой: запуск, сценарии, ошибки | не «докидывает фичи» |
| **designer** | UX/UI-решениями, если проект в домене web/ui | не трогает бизнес-логику |
| **docs** | README, CONTEXT, комментарии к интерфейсам | не рефакторит код |

## Правила

1. **Контракт — профиль и план.** Все роли работают по одному
   `.agent-forge/profile.json` и `.agent-forge/plan.md`. Роль не может
   изменить контракт — только предложить, а решение принимает человек.
2. **Порядок жёсткий:** planner → (researcher) → implementer → reviewer →
   tester → (docs). Не перескакивай: reviewer не начинается, пока
   implementer не закончил.
3. **Одна роль — один проход.** Не совмещай implementer и reviewer в одном
   проходе — свежий взгляд требует смены контекста.
4. **Результат роли — артефакт**, а не «поговорили»: код, заметка, список
   багов, отчёт. Артефакты — в `.agent-forge/` или в коде проекта.
5. Если задача маленькая (одна сессия) — роли не нужны, работай
   напрямую через `plan`.

## Как оркестрировать (агентский режим)

Если твой харнесс умеет субагентов — каждую роль можно отдать субагенту:

1. Planner (ты или субагент) составляет каркас: этап, задачи, критерии.
2. Перед каждой ролью дай субагенту: профиль, план, текущее состояние
   репозитория и **контракт роли** (что он владеет, чего не делает).
3. Результаты ролей складываются в `.agent-forge/` или в код.
4. После каждой роли — сверка с планом: этап движется к цели?

## Что дальше

После завершения этапа — проверь его результат (скил `improve`, если
нужна итеративная доработка) и переходи к следующему пункту плана.
